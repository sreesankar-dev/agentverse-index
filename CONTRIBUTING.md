# Contributing

Thanks for helping grow the list! Please follow these rules so it stays useful.

## Adding a skill

1. The skill must be **public** and have a `SKILL.md` (or ship as a Claude Code plugin).
2. **Link to the original repo**, ideally to the skill's folder. Do not copy skill files into this repo.
3. Add it to the best-fitting category, using this format:

   ```markdown
   - [skill-name](https://github.com/owner/repo/tree/main/path/to/skill) - One short sentence on what it does.
   ```

4. Keep the description short, factual and free of marketing words ("best", "ultimate").
5. One skill per line. Avoid duplicates; search the README first.
6. If no category fits, propose a new one in your PR.

## Pull request checklist

- [ ] The link works and points to the original author's repo
- [ ] The description is one sentence and ends with a period
- [ ] The entry is in the right category
- [ ] I checked the skill does nothing malicious (no hidden network calls, credential grabbing, etc.)

## Removing or fixing entries

Dead link, abandoned repo or wrong description? Open an issue or a PR. Weekly CI also flags broken links.
